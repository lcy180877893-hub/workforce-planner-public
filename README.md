# 工程劳动力测算 · 开源插件服务端与内嵌界面

根据工程量、施工时间与工效库，结合当前 ChatGPT 会话确认的施工顺序，生成劳动力方案、人员柱状图与施工横道图。版本为 `0.19.1-rc.1`，采用 [MIT 许可证](LICENSE)。开发者：李旭峰；支持邮箱：lixufeng@cccc4-2ksa.com。

本仓库提供可自行部署的 MCP 服务端、四页网页/ChatGPT 内嵌界面和测试源码，**不提供由作者持续运营的公共网站，也不代表插件已经在 ChatGPT 目录上架**。只下载源码或在 GitHub 点 Star，不会自动在 ChatGPT 中启用插件。需要自行运行服务、配置身份认证与数据库，再在支持的客户端中连接自己的 MCP 地址。仓库没有可直接安装的 `plugin.json` 插件包；现有私有测试插件仍独立保留。

当前版本沿用已实现的 PostgreSQL + Auth0 架构，不能直接双击 HTML 使用，也没有取消认证的本地存储回退。部署属于可选的自托管方式，不要求使用作者的云账号或已有网站。设置步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)，验证边界见 [RELEASE-STATUS.md](RELEASE-STATUS.md)。

## 使用方式

登录后使用四个页面：劳动力测算、比例设置、测算历史、工效库。所有已登录用户都可查看公共默认工效；新增、修改和隐藏工效保存为本账号的个人版本，仅本人的列表与后续测算生效，不改公共库或其他账号。每个账号只能查询、读取、删除自己的测算历史。浏览器草稿、比例与内嵌界面状态也按账号区分。

施工判断由用户当前的 ChatGPT 会话进行，不调用模型 API、不要求模型 API 密钥。点击测算先准备工程资料，内嵌版通过宿主发送给当前会话，独立网页提供可复制的测算请求；连接**自行部署的 MCP 服务**后，ChatGPT 先读取资料并确认缺失条件，再提交完整施工审查生成方案。网页本身不后台调用 ChatGPT，也不直接使用 ChatGPT 登录 cookie。客户端是否允许创建连接、使用内嵌界面及所需账号权限，以实际平台能力为准。

保留既有排程、劳动力柱状图、横道图及缩放。工期足够时优先顺序施工；不足时比较经审查允许的单班组白班搭接、多班组白班搭接、早晚班两套人员、多班组白班等适用方案，技术前置不会因赶工被取消。不自动补造工效或养护固定天数。

## 数据与安全边界

- 历史保存在 PostgreSQL，不依赖 Render 的临时本地文件。所有历史 SQL 都以服务器验证的用户身份限定，不接受工程量中的用户编号作为所有者。
- 用户身份由 Auth0 的 `iss + sub` 派生稳定标识；邮箱、名称、客户端角色字段不能提升管理员权限。网站使用 OIDC 安全 cookie，MCP 使用已验证的 OAuth Bearer，二者不互相回退。
- 网站写请求要求同源与 CSRF 校验；MCP 工具声明 read/write scopes。个人工效查询与写入均限定服务器验证的账号；公开网页和工具不提供共享库改写入口。数据库连接强制验证 TLS 证书。
- 当前隔离采用服务端所有权检查，**不是 PostgreSQL RLS**。数据库连接凭据仅限服务端；不能直接给用户连接数据库。
- 同账号同 requestId 重试不重复保存；不同输入复用编号会拒绝。删除历史不会重置每日保存额度。
- 免费试运行保护：每用户最多保存 100 条、每天最多新增 20 条，全站最多 500 条，单方案最多 1 MiB。达到上限明确提示，不自动删除记录。项目最多 100 项、约 5 年；这些是本应用保护值，不是云厂商额度。

内置默认库共 158 条：原有 47 条，加用户授权整理的 111 条分类目录；总计 46 条可用、112 条不可用。新增目录全部保留不可用、工作内容待补充、产量与班组未填写，不能直接测算。发布包包含这些默认条目，但不包含用户个人覆盖库、真实测算历史、原始 Excel/Word、截图、隧道配置或密钥，不连接或扫描作者的私有文件。初始化只插入缺项，不覆盖已有公共条目或恢复已删除条目。个人修改存入独立覆盖表；应用保护上限为每人 500 条修改记录、个人有效库 500 条、全站 5000 条修改记录，达到上限不自动删除数据。

### 工效来源与适用性

基础条目来源标记为用户提供的跨项目人员工效推荐表；111 条目录按用户提供的地基基础、主体结构分类图片整理。来源说明保留在条目的 `source`、`notes` 中，不意味着原始表格、图片或第三方资料版权转让。第三方依赖仍遵循其各自许可证。使用者应核对提供者有权分享的数据，并按项目类型、班组组成、工作时长、单位、设备及现场条件复核工效；本库不是沙特法定定额、规范或安全审批依据。无工效条目不能用零值或猜测值代替。

## 开发验证

使用 Node 24（`>=24.19 <25`）和锁定的 pnpm 11.25.0：

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm preflight
```

测试用合成账号、离线签名 JWT、SDK 登录桩和 PGlite 执行 SQL，不使用真实私有记录或真实登录密钥。它们不替代部署后的 Auth0/Neon/ChatGPT 实测。

只有配置安全环境变量后才可运行 `pnpm migrate` 和 `pnpm start`；`.env.example` 仅列出空配置项，应用不会自动加载该文件，需使用主机的安全环境变量配置。配置缺失时拒绝启动，不退回原私有文件存储。旧本地服务入口与模型 API 客户端未包含在本开源包中。仅 `productivity-store.js` 中的纯工效校验函数被服务端复用，不会实例化其本地文件存储类。

`package.json` 的 `private: true` 仅用于阻止误发布到 npm，与 GitHub 仓库公开状态无关。发布前可运行 `pnpm preflight --manifest` 审查当前精确文件白名单；此检查不能替代人工检查 Git 提交历史。

## 可选免费自托管的限制

Render 免费 Web 服务空闲后会休眠，初次唤醒可能较慢；不承诺全天候可用。数据库使用独立 Neon Free，不使用会过期的 Render 免费数据库。Auth0 使用免费租户默认域名，不启用收费功能。超过任一提供商免费限额时先暂停或调整，不自动升级。详见 [Render Free](https://render.com/docs/free)、[Neon Pricing](https://neon.com/pricing)、[Auth0 Pricing](https://auth0.com/pricing)。

本工具提供资源估算，不代替项目技术审批、合同工期承诺或施工安全验收。
